# Wildfront: notes for Claude Code

- Design source of truth: `docs/GDD.md`. Log any decision the GDD doesn't cover in `docs/DECISIONS.md`.
- Engine: Godot 4.7, GDScript (the installed build has no .NET). The console exe is at `F:\Godot\exe\Godot_v4.7.2-stable_win64_console.exe`.
- The server is authoritative on a fixed 600 ms tick (`shared/sim.gd`, fixed phase order in `Sim.step()`).
  Clients only send intents and render snapshots. Never put game rules in `client/`.
- Game rules live in `shared/` (pure `RefCounted` classes, no scene nodes) so tests, bots, the balance
  simulator and the LAN host all run the same code.
- Content lives in `data/*.json`, loaded and validated by `shared/db.gd` (`DB.errors` must stay empty; see
  `tests/test_data.gd`). Balance changes should be data edits, not code edits.
- Use only the original in-game names in the GDD. Never use OSRS names, models, sprites, sounds or data.
- Art follows `docs/ASSETS.md`: models/clips are generated by `art/blender/` (run `python tools/build_assets.py`),
  never hand-edited in Godot. Check screenshots (`python tools/build_assets.py shots ...`) after visual changes.
- Environment follows `docs/ENVIRONMENT.md`: gameplay data owns the map. Dressing logic is `client/match/env/`;
  `tests/test_environment.gd` must pass. Map screenshots: `res://tools/dev/map_shots.tscn`.
- GDScript packed arrays are values: `(d["k"] as PackedVector3Array).append(...)` changes a copy. Take it out,
  change it, store it back.
- Run the tests before calling anything done:
  `godot --headless --path . --script res://tests/run_tests.gd` (exit code 0 = all pass; script errors count as failures).
- GDScript gotcha: `var x := dict[...]` / `{...}.get()` can't infer a type, so annotate it (`var x: String = ...`).
  Warnings are errors here.
- Don't make git commits; the owner reviews and commits.
